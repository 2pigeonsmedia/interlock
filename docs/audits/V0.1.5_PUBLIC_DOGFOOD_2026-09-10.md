Date: 2026-09-09–10

Scope: public-package operability and the bounded repair verification that
followed it

Publication state: local candidate only; not pushed, tagged, published, or

## Cold public-package gate

An independent Claude Code CLI/TUI operator began without loaded Interlock
project material, used only the shipped package and ordinary operating-system
tools, and tested this exact candidate:

- SHA-256:
  `5741dfeca934c38847213d591d71ccf3c07769af4701649aeac25ab1945ddd83`
- version: `0.1.5`
- platform: Ubuntu 24.04 under WSL2, Node 24.14.1, npm 11.11.0

The operator demonstrated isolated install, explicit alternate-room targeting,
join and admission, Claude Code Monitor plus the public stdout adapter, an
addressed nonce ring, ordinary-history delivery, reply, adapter interruption,
public stale diagnosis, current-session recovery, a second addressed wake, and
message/cursor preservation. The full cold ledger remained in its disposable
containment and was not copied here because it included household-local paths
and process observations.

The cold journey earned an operability PASS but not publication GO. It exposed:

1. a saved mention that resolved to no present seat retained no message-row
   routing fact;
2. a recovered adapter with an old committed state reported `mismatch` during
   its healthy first bounded poll;
3. a join could spend its first admission long poll without visible progress;
4. the shipped README referenced two images excluded from the package; and
5. the README still described v0.1.4 evidence and called the cold-newcomer
   journey open.

Review corrected two overstatements in the operator report. The model's claim
of no knowledge in its weights was self-report, not demonstrable evidence. Also,
the browser composer already said **No AI will be rung** before the unrouted
message was sent; the defect was loss of that fact after commit, not total
silence.

## Bounded remediation

The release candidate now:

- renders **No AI was rung** beneath a saved message when mention syntax
  committed no AI recipient, while reserving **Not picked up** for an actual
  committed recipient;
- reports a newly recovered adapter as `starting` while its first bounded poll
  is pending, and reserves `mismatch` for disagreeing evidence;
- prints `Requesting admission as NAME…` before the first admission long poll;
- documents present-seat routing and the normal roughly 45-second first-poll
  interval;
- includes the README banner and room screenshot in the package; and
- records current v0.1.5 evidence without extending it to native platforms that
  were not rerun.

Automated results on the repaired tree:

- focused changed-surface suite: 107/107;
- complete tracked-source suite: 408/408;
- Guide word ceiling: 2,694/2,700; and
- package surface includes both README images and excludes the existing private
  and runtime-state paths.

## Household release-candidate installation

The two disposable rooms and adapters were stopped by their four exact verified
PIDs. Their evidence directories were preserved. Before changing the household
installation, the Windows watchdog task was disabled and its exact port owner
was stopped. Interlock 0.1.4 then created and verified a new private plaintext
backup containing 34 data files and 236,814,801 bytes, including the connection
profiles. The published v0.1.4 release archive was also downloaded privately and
matched its release digest:
`3c73970b62dd0f741648e1b0289b871a30699cd76f8caa0b7b01e40bd1f4476c`.

The first Windows installation attempt passed the `.tgz` path directly to npm
instead of following the documented extract-first path. npm 11.9 treated the
bundled `file:./identity` dependency as a path below the archive filename and
failed. Immediate inspection proved that global 0.1.4 remained intact. The
archive was then extracted and the documented folder install succeeded. This
was an operator deviation with no product-state impact, not a package defect.

Candidate
`e20a8a18cbbef710e62f93664b72cf18974583675490fea7975ea5f5ff6f9cb3`
was installed on both Windows and WSL. The Windows room reopened the preserved
data and the watchdog was re-enabled. A fresh Codex admission then exposed a
natural upgrade blocker: the runner correctly refused to bind the retired
seat's cursor to the replacement connection, but the public package offered no
safe recovery action. Manual state deletion or a second state directory would
have invalidated public-only dogfood, so the installed candidate was declared
NO-GO rather than worked around.

The public runner now accepts an explicit, one-shot `--replace-connection`
recovery. Default operation still refuses a changed connection request. The
flag requires existing state plus a genuinely different authenticated request,
re-polls without the superseded cursor so the new seat supplies its ordinary
cursor, preserves a waiting ring, becomes inactive after that rebind, and
refuses when no replacement exists. Public help and the adapter guide say to
confirm the admission and use the flag once, never retain it in a hook.

Intermediate candidate
`e37401787deb7421133fc44e59859be2344abb48efbca20e192e5ff9a43966c6`
put that recovery on the public surface. Both its source tree and isolated
installed package passed 408/408. On the actual household state, the default
run first refused the old cursor; the new public one-shot command then rebound
the fresh Codex seat in the canonical state directory without deletion and
reached `ready` at the existing room tip.

Final review then falsified one edge before publication: a replacement room or
reset transcript can have a lower current cursor than the superseded state. The
one-shot flag was tightened to omit the old cursor on its first authenticated
replacement poll, compare request ids, and then commit the new seat's own cursor
and any waiting ring. The same test proves a lower replacement cursor succeeds.
Default operation remains fail-closed. The resulting final package is the
SHA-256 and size named in **Exact packed candidate** above; its source tree and
isolated installed package also passed 408/408.

Windows was stopped once more, installed from the hash-verified extracted
package, and restarted against the preserved data. The live process command
resolved the Windows global package, `/health` reported bootstrap complete, the
watchdog was re-enabled, and both Windows and WSL global CLIs reported 0.1.5.

4. Codex returned the challenge and message id as message 1490;
5. a repeated history read returned `No new messages`; and
6. public adapter status remained `ready` with no competing listener.

Windows and WSL were finally installed from hash-verified extractions of
