## Cold public-package gate

An independent Claude Code CLI/TUI operator began without loaded Interlock
project material, used only the shipped package and ordinary operating-system
tools, and tested this exact candidate:

- SHA-256:
  `5741dfeca934c38847213d591d71ccf3c07769af4701649aeac25ab1945ddd83`
- version: `0.1.5`
- platform: Ubuntu 24.04 under WSL2, Node 24.14.1, npm 11.11.0

The operator demonstrated isolated install, explicit alternate-room targeting,
join and admission, Claude Code Monitor plus the public stdout adapter, an
addressed nonce ring, ordinary-history delivery, reply, adapter interruption,
public stale diagnosis, current-session recovery, a second addressed wake, and
message/cursor preservation. The full cold ledger remained in its disposable
containment and was not copied here because it included household-local paths
and process observations.

The cold journey earned an operability PASS but not publication GO. It exposed:

1. a saved mention that resolved to no present seat retained no message-row
   routing fact;
2. a recovered adapter with an old committed state reported `mismatch` during
   its healthy first bounded poll;
3. a join could spend its first admission long poll without visible progress;
4. the shipped README referenced two images excluded from the package; and
5. the README still described v0.1.4 evidence and called the cold-newcomer
   journey open.

Review corrected two overstatements in the operator report. The model's claim
of no knowledge in its weights was self-report, not demonstrable evidence. Also,
the browser composer already said **No AI will be rung** before the unrouted
message was sent; the defect was loss of that fact after commit, not total
silence.

## Bounded remediation

The release candidate now:

- renders **No AI was rung** beneath a saved message when mention syntax
  committed no AI recipient, while reserving **Not picked up** for an actual
  committed recipient;
- reports a newly recovered adapter as `starting` while its first bounded poll
  is pending, and reserves `mismatch` for disagreeing evidence;
- prints `Requesting admission as NAME…` before the first admission long poll;
- documents present-seat routing and the normal roughly 45-second first-poll
  interval;
- includes the README banner and room screenshot in the package; and
- records current v0.1.5 evidence without extending it to native platforms that
  were not rerun.

Automated results on the repaired tree:

- focused changed-surface suite: 107/107;
- complete tracked-source suite: 408/408;
- Guide word ceiling: 2,694/2,700; and
- package surface includes both README images and excludes the existing private
  and runtime-state paths.

## Focused live verification of the exact package

A new disposable room was started from packed candidate
`17ba812066f895fd244a45a7ff7b2ce3637a656a7dfd0d0953c287c62dc6a4c2`
on a port confirmed free in both Linux and Windows views. The earlier cold-test
room was left untouched. Its join and browser files are byte-identical to the
final package named above; final review subsequently strengthened only the
runner's immediate-recovery classification and its test, plus source-only
evidence wording.

Observed results:

- join printed the exact room target and `Requesting admission as Siskin…`
  immediately, before the pending wait completed;
- an addressed message committed Siskin as its recipient;
- the first Codex injection was contaminated by my test harness setting a
  contained `HOME`, which hid the active Codex rollout. The host rejected it, Interlock
  failed loudly, and the ring remained eligible;
- correcting only the harness boundary—an explicit contained Interlock
  connection directory while retaining the host's real home—allowed the same
  ring to be accepted, committed at cursor 1, read through ordinary history,
  and answered as the next message;
- the host delivered that queued nudge late. A repeated ordinary history read
  returned `No new messages`, so the delayed nudge caused neither duplicate
  delivery nor duplicate reply;
- restricted diagnostic commands could list the outside-sandbox profile and
  adapter files but could not verify their ownership, producing one false
  `stale` status and one refused profile read. Running the same public commands
  in the adapter's host context reported `ready` and read the profile normally;
- after stopping only the verified adapter PID and allowing its committed state
  to leave the freshness window, public status reported `stale` and printed the
  exact current-session recovery command;
- immediately after that command, status reported `starting — adapter owns the
  connection and is completing its first bounded poll after recovery`;
- the same adapter then reached `ready` with its cursor preserved; and
- a browser message containing `@Unseen` committed an empty recipient list. The
  composer said **No AI will be rung** before send, and the saved message row
  said **No AI was rung** afterward.

The strengthened final package was then installed in a second fresh prefix and
passed its own 408/408 suite. Its exact runner replaced the disposable Siskin
adapter while the predecessor's committed state was still fresh. Public status
reported `starting` during the new runner's first poll and `ready` after that
poll committed, closing the immediate-recovery edge with live evidence from the
final artifact.

The containment-induced observations were attributed to my harness errors, not
hidden as product failures. None acknowledged or lost a message.

the cold gate. This record does not authorize publication. Publication, tagging,

remain separate actions.

boundary. Native Ubuntu, native macOS, and a real screen-reader journey also
